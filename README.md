# Stelline 개발 환경

## 구조

- `stelline/static/`: 공개 화면의 HTML·기능별 JavaScript·공통 `assets/` 디자인/API 도우미입니다. 공개 화면은 모두 이 방식으로 제공됩니다.
- `stelline/templates/`: 로그인 및 관리자처럼 서버 세션과 보호된 데이터를 즉시 렌더링해야 하는 화면입니다.
- `stelline/apis/`: 기능별 HTTP API입니다. 각 기능 폴더는 `routes.py`(라우트 등록), `service.py`(요청 처리 로직), 필요 시 `tasks.py`(백그라운드 작업)로 구성됩니다. `reports.py`·`turnstile.py`는 기능 간 공용 헬퍼입니다.
- `stelline/database/`: 연결 생성, 코드 기준 스키마, 마이그레이션입니다. `data/`에는 노래방 번호 기본 목록 같은 초기 데이터가 들어 있습니다.
- `stelline/content/`: 화면에 박아 둔 문구·그림 중 관리자가 고칠 수 있는 것들입니다. `registry.py`가 목록과 상한을, `store.py`가 저장·검증을, `images.py`가 올린 파일의 형식 확인을 맡습니다. 아래 `사이트 문구·그림 고치기` 참고.
- `stelline/background_tasks/`: 운영에서만 시작되는 YouTube·검색·Bugs 동기화 작업입니다.
- `tests/`: pytest 스위트. 단위/화면 테스트는 DB 없이, `*_integration.py`는 실제 MySQL로 실행됩니다. 자세한 내용은 `README_DEV.md` 참고.

## 화면 공통 규칙

- 모든 공개 화면은 위쪽에 같은 **머리말 줄**(`.site-header`)을 둡니다. 어느 화면에서든 다른 기능으로 바로 갈 수 있어야
  "메인으로 돌아갔다가 다시 들어가는" 왕복이 없습니다. 지금 보고 있는 화면은 `aria-current="page"`로 표시합니다.
  화면을 새로 추가하면 **모든 화면의 머리말에 링크를 같이 추가**하고, 메인 화면 카드와 같은 `data-button-key`를 붙이세요.
- 머리말 메뉴와 메인 화면 카드는 `assets/nav.js` 하나가 함께 맡습니다. 관리자에서 숨긴 기능이
  다른 화면 메뉴에는 남아 있으면 안 되기 때문입니다. 아래 `메인 화면 버튼 켜고 끄기` 참고.
- 여백·모서리·글자 크기는 `site.css` 위쪽 토큰(`--panel-pad`, `--radius-card`, `--gap-page` 등)에서 정합니다.
  화면별 CSS에 값을 직접 적으면 화면마다 간격이 어긋납니다.
- 값이 두세 개뿐인 선택은 목록을 여닫는 대신 `.segmented`(탭)로 한 줄에 나란히 둡니다.
- 카드 하나가 통째로 하나의 동작이면 `.card.is-link`로 카드 자체를 버튼으로 만듭니다.
  아래에 버튼 줄을 따로 두지 않아 카드가 짧아지고, 누를 곳도 넓어집니다.

## 환경 분리

- 운영은 `.env`와 운영 RDS를 사용합니다. 운영 DB에 자동으로 스키마를 적용하지 않습니다.
- 개발은 `.env.development`와 Docker의 `stelline_dev` MySQL을 사용합니다. 개발 기본값은 외부 API 호출과 FCM 발송을 비활성화합니다.

## 개발 시작

1. `docker compose -f docker-compose.dev.yml up -d`로 개발 DB를 시작합니다.
2. `pip install -r requirements.txt` 후 `./run-development.ps1`을 실행합니다.
3. `AUTO_CREATE_SCHEMA=true`이면 코드 기준 스키마가 빈 개발 DB에 자동 생성됩니다.

## 스키마 변경

스키마는 `stelline/database/schema.py`의 `MIGRATIONS`가 기준입니다. 새 변경은 새 버전의 migration을 추가하고, 개발 DB에서는 앱을 재시작하거나 `python -m stelline.database.migrate`로 적용합니다. 운영 배포 시에는 백업 후 이 명령을 명시적으로 실행하세요.

운영에서 `AUTO_CREATE_SCHEMA`는 항상 `false`로 유지하세요.

## 관리자 HTML로 개발 데이터 채우기

운영 관리자 페이지에서 저장한 HTML 파일은 개발 DB의 데이터 스냅샷으로 사용할 수 있습니다. 이는 역마이그레이션이 아니라 개발용 시드 데이터 import입니다.

```powershell
$env:APP_ENV = 'development'
python -m stelline.database.import_admin_html "C:\path\관리자 페이지.html" --dry-run
python -m stelline.database.import_admin_html "C:\path\관리자 페이지.html" --replace
```

`--replace`는 HTML에 포함된 개발 테이블 데이터를 비운 뒤 해당 스냅샷으로 바꿉니다. 개발 환경에서만 실행되며, 운영 FCM 토큰과 제거된 게임 리더보드는 가져오지 않습니다.

## 사이트 문구·그림 고치기

화면 곳곳의 안내 문구와 안내 그림은 코드를 고치지 않고 관리자 페이지 → **사이트 문구·그림** 탭에서
바꿉니다. 메인 화면 소개 문구, 검색 화면의 단계 안내 그림처럼 "가끔 바뀌지만 배포까지 할 일은
아닌" 값들이 여기 모여 있습니다.

### 어떻게 동작하나

기본값은 계속 **HTML과 코드에** 있습니다. DB(`site_contents`)에는 **관리자가 바꾼 것만** 들어갑니다.

| DB 상태 | 화면 |
| --- | --- |
| 행 없음 | `stelline/content/registry.py`의 기본값(= 지금 HTML에 적힌 값) |
| 값 있음 | 그 값 |
| 비움(`cleared`) | 그 자리를 **통째로 없앰**(빈 칸이 남지 않음) |

그래서 DB가 비어 있어도, 조회에 실패해도, API가 죽어도 화면은 지금 모습 그대로 보입니다.
값을 못 받아오면 `content.js`가 아무것도 건드리지 않아 HTML에 적힌 문구가 그대로 남기 때문입니다.

### 레이아웃이 깨지지 않게 하는 장치

문구가 길어지거나 그림 비율이 어긋나면 화면이 밀립니다. 그래서 저장 자체를 막습니다.

- **문구**: 항목마다 최대 글자 수가 있고, 여러 줄 항목은 줄 수도 제한합니다. 관리자 화면에
  글자 수 세기가 붙어 있고(상한을 넘으면 빨갛게 표시), 브라우저 검사를 건너뛴 요청도 서버가 막습니다.
- **그림**: 형식(PNG·JPEG·WebP·GIF)·용량·최소/최대 크기·가로세로 비율을 항목마다 정합니다.
  형식은 확장자가 아니라 **파일 앞머리(매직 바이트)**로 확인하므로 이름만 `.png`인 파일은 통과하지 못합니다.
- **미리보기**: 저장 전에 실제 화면과 같은 크기·글자 크기로 보여 줍니다. 그림은 공개 화면과 같은
  상자(단계 그림 140px `contain`, 공지 그림 16:9 `cover`)에 넣어 잘림 여부까지 미리 보입니다.
- CSS 쪽에도 상자 규칙을 두어, 어떤 경로로 값이 들어와도 칸이 화면을 밀어내지 않습니다.

### 항목을 새로 늘리려면

1. `stelline/content/registry.py`의 `CONTENT_ITEMS`에 항목을 추가합니다(문구면 글자 수 상한, 그림이면 크기·비율 범위).
2. 화면 HTML의 그 자리에 `data-content-key="<키>"`를 붙입니다.
   - 값이 비면 바깥 상자째 사라져야 하면 `data-content-hide="<선택자>"`를 함께 붙입니다.
   - 여러 줄을 `<li>` 목록으로 그리려면 `data-content-list`를 붙입니다.
   - 안의 문구가 모두 비면 사라져야 할 상자에는 `data-content-block`을 붙입니다.
   - 기본값이 비어 있는 항목은 HTML에도 `hidden`을 적어 둡니다(값이 생기면 켜집니다).
3. `tests/test_content_units.py`가 **항목 목록과 화면 HTML이 서로 맞는지** 검사합니다.
   화면에 붙이지 않은 항목이나, 목록에 없는 키를 쓴 화면이 있으면 테스트가 실패합니다.

### 지금 고칠 수 있는 것

메인 화면(소개 문구·공지 제목/내용/그림·세 칸의 설명), 검색 화면(소개 문구·공지·목록 설명·
도와주는 방법 제목과 설명·그 목록·PC와 모바일 단계 그림 7장과 그 설명·그림 안내),
노래방/오프라인 화면의 소개 문구, 조회수 축하 화면의 알림 안내 문구와 달성 목록 설명,
모든 화면 공통 꼬리말입니다.

조회수 축하 화면의 안내 문구(`앱 설치 없이 알림을 받으려면…`)는 원래 알림 상태 줄과 한 자리를
같이 썼습니다. 상태가 문구를 덮어써서 고칠 수가 없었기 때문에, 안내 문구에 제 줄을 주고
상태 줄은 **알릴 것이 있을 때만** 나오도록 나눴습니다(`app.js`의 `showStatus`·`resetStatus`).

꼬리말은 **모든 화면이 같은 항목 하나**를 씁니다. 화면마다 따로 두면 같은 문구를 여러 번
고쳐야 하고, 어느 화면이 어느 값을 쓰는지도 헷갈립니다.

단계 그림을 비우면 그 단계 칸이 사라지고 **남은 단계의 STEP 번호가 다시 매겨집니다.**
`STEP 1, STEP 3`처럼 번호가 비는 일이 없습니다.

## 관리자 페이지에서 데이터 수정하기

표가 열한 개라 한 화면에 전부 펼치면 무엇을 고칠지 찾는 데만 시간이 걸립니다. 그래서 위쪽 **탭**으로
`메인 화면 · 노래방 · 검색 점검 · 오프라인 · 사용자 제보 · 읽기 전용 통계` 묶음 중 하나만 보여 줍니다.

- 어떤 표가 어느 탭에 들어가는지는 `stelline/admin/routes.py`의 `group` 값과 `TABLE_GROUPS` 순서로 정합니다.
- 고른 탭은 브라우저(`localStorage`의 `stelline.admin.group`)에 남습니다. 저장 후 화면이 새로 그려져도
  **같은 자리에서 이어서** 작업할 수 있습니다.
- 양식의 칸 이름은 `labels`, 표의 열과 머리글은 `list_fields`·`list_labels`에서 정합니다. 둘 다 한글로 적어 두세요.
- 사용자 제보처럼 관리자가 직접 넣을 일이 없는 표는 `collapse_form`을 켜서 양식을 접어 둡니다.
  접혀 있어도 표에서 행을 클릭하면 자동으로 펼쳐지며 수정 모드가 됩니다.

노래방 곡처럼 항목이 수백 개인 표는 훑어보기 좋은 열만 보여줍니다
(곡명·가수·구분·종류·TJ·금영·참여 멤버). 표에서 뺀 열도 **행을 클릭하면 양식에 그대로 채워집니다.**
값이 비어 있으면 `—`로 표시되어 무엇이 덜 채워졌는지 바로 보입니다. 표시할 열은
`stelline/admin/routes.py`의 `list_fields`에서 정합니다.

행을 클릭하면 **수정**이고, 관리 칸의 `복제`를 누르면 같은 값이 **추가** 모드로 채워집니다.
비슷한 곡을 하나 더 만들 때 값을 조금만 고쳐 저장하면 되고, 원래 행은 그대로 남습니다.

노래방 곡 목록은 화면에서 **랜덤순·가나다순**으로만 보여 주므로 정렬 순서를 따로 정하지 않습니다.


관리자 페이지의 각 양식은 **추가**와 **수정** 두 가지로 함께 씁니다.

1. 양식 아래 표에서 고칠 행을 클릭하면 값이 양식에 채워지고 버튼이 `수정 저장`으로 바뀝니다. 선택한 행은 노란색으로 표시됩니다.
2. 값을 고치고 `수정 저장`을 누르면 그 행만 바뀝니다. 새 항목을 넣으려면 `새 항목 추가로 돌아가기`를 눌러 추가 모드로 되돌립니다.
3. 수정 대상은 서버가 서명한 토큰으로 지정되므로, 브라우저에서 값을 바꿔 다른 행을 건드릴 수 없습니다.

빈 칸의 의미는 추가할 때와 수정할 때가 다릅니다.

- **추가**: 빈 칸은 저장에서 빠지고 열의 기본값이 들어갑니다.
- **수정**: 빈 칸은 "값 없음"으로 저장합니다. 다만 값이 반드시 있어야 하는 열(NOT NULL)은 지울 수 없으므로 **기존 값을 그대로 둡니다.**

## 노래방 번호 데이터

노래방 곡은 `karaoke_songs`, 필터에 쓰는 멤버 목록은 `karaoke_members`, 사용자 제보는 `karaoke_reports`에 저장됩니다.

기본 목록(`stelline/database/data/karaoke_seed.tsv`)을 넣는 방법은 두 가지입니다.

- 관리자 페이지 → `노래방 번호` → `여러 곡 한 번에 등록하기` → `기본 목록 가져오기`
- 명령줄: `python -m stelline.database.karaoke_seed`

두 방법 모두 **곡명과 가수가 같은 곡은 새로 만들지 않고 기존 곡의 값만 갱신**하므로 여러 번 실행해도 안전합니다. 이때 곡의 id도 그대로 유지되어 사용자가 공유한 목록 링크가 계속 동작합니다. `기존 곡을 모두 지우고 새로 넣기`를 켜면 id가 새로 매겨져 기존 공유 링크는 끊깁니다.

### 참여 멤버를 적을 때

유닛과 멤버 구성은 시간에 따라 바뀝니다. `karaoke_members`의 데뷔일·졸업일·이전 유닛이 그 기준입니다.

- 아이리 칸나: 2024-12-02 졸업. **그 뒤에 나온 곡에는 넣지 않습니다.**
- 사키하네 후야: 2025-09-20 합류. **그 전에 나온 곡에는 넣지 않습니다.**
- 아야츠노 유니: 미스틱 → 에버리스(2025-09-20 개편). 현재 유닛은 에버리스, 이전 유닛에 미스틱이 적혀 있습니다.

졸업일과 데뷔일은 **데이터가 맞는지 검증하는 용도로만** 쓰고 공개 화면에는 내보내지 않습니다.
멤버 필터에는 소속 유닛으로만 묶여서 나옵니다.

곡의 `발매일`을 시드 파일에 적어 두면 이 관계를 나중에도 검증할 수 있습니다.
발매일은 데뷔일·졸업일과 마찬가지로 **검증용이라 공개 화면과 관리자 양식에는 나오지 않습니다.** `tests/test_karaoke_seed.py`의
`test_seed_members_were_active_when_the_song_was_released`가 시드 파일 전체를 이 규칙으로 검사하므로,
졸업한 멤버를 이후 곡에 넣거나 데뷔 전 멤버를 과거 곡에 넣으면 테스트가 실패합니다.

기본 시드의 단체곡 참여 멤버는 공식 뮤직비디오·커버 영상 설명의 크레딧을 그대로 옮긴 것입니다.
크레딧이 없는 곡은 추측해서 채우지 않고 비워 둡니다. **같은 앨범이라도 트랙마다 참여 멤버가 다를 수 있으니**
타이틀곡 크레딧을 앨범 전체에 적용하지 마세요.

새 곡 여러 개를 한 번에 넣을 때는 같은 화면의 붙여넣기 칸에 표를 그대로 붙여 넣으면 됩니다. 첫 줄에 `곡명 가수 TJ KY` 같은 머리글을 넣으면 열 순서를 바꿔도 되고, 머리글이 없으면 `곡명 · 가수 · TJ · KY` 순서로 읽습니다. 번호가 없는 칸은 `-` 또는 빈 칸으로 둡니다.

## 조회수 달성 배지

조회수 축하 카드의 배지는 달성 기록의 크기에 따라 색이 달라집니다. 훑어보다가도 큰 고비가 눈에 걸려야 합니다.

- 100만 미만: 기본(어두운 반투명)
- 100만 이상: 파랑(`--primary-hover`)
- 1000만 이상: 금색(`--milestone-top`)

기준과 색은 `congratulation.js`의 `is-million`·`is-ten-million`과 `site.css`의 같은 이름 규칙에서 정합니다.

## 다크 모드

다크 모드는 노래방 모드와 분리된 사이트 전역 설정입니다.

- 모든 공개 화면의 오른쪽 아래에 있는 동그란 버튼으로 켜고 끕니다.
- 고른 값은 브라우저(`localStorage`의 `stelline.theme`)에 남아 새로고침·페이지 이동 후에도 유지됩니다.
- 고른 적이 없으면 운영체제의 밝기 설정을 따라갑니다.
- 배색은 `stelline/static/assets/site.css`의 `:root[data-theme="dark"]` 한 곳에서 정의합니다.
  **화면별 CSS에는 색을 직접 적지 말고 토큰(`var(--surface)` 등)을 쓰세요.** 그래야 두 배색이 함께 맞습니다.
- 노래방 모드는 이제 글씨·번호 크기만 키웁니다. 예전에 노래방 모드를 켜 두었던 사람은
  처음 한 번 다크 모드로 옮겨집니다.

## 메인 화면 버튼 켜고 끄기

메인 화면 위쪽의 기능 카드와 **모든 화면 머리말의 메뉴**는 `main_buttons` 테이블 하나로 함께 관리합니다.
관리자 페이지의 `메인 화면 버튼`에서 `표시 여부`를 `숨김`으로 바꾸면 두 곳에서 같이 사라지고,
`표시 순서`가 작을수록 앞에 옵니다.

카드에는 버튼 이름과 함께 **무엇을 하는 곳인지 한 줄 설명**이 붙습니다. 설명은 화면에 적어 두는 값이라
DB가 아니라 `stelline/static/index.html`에서 고칩니다(`label`은 DB 값이 우선합니다).

- `버튼 키`는 `stelline/static/index.html`의 `data-button-key` 값과 짝을 이룹니다. **바꾸지 마세요.**
  지금 쓰는 키는 `search` · `karaoke` · `congratulation` · `offline` 입니다.
- 화면에 새 버튼을 추가할 때는 HTML에 `data-button-key="..."`를 붙이고 같은 키로 행을 하나 추가하면 됩니다.
- DB에 없는 키의 버튼은 건드리지 않고 그대로 보여 줍니다. 설정을 못 불러와도 버튼이 사라지지 않습니다.
- 직전 설정을 브라우저에 저장해 두므로, 숨긴 버튼이 잠깐 보였다 사라지지 않습니다.
- `버튼 이름`은 메인 화면 카드에만 반영합니다. 머리말은 자리가 좁아 화면에 적어 둔 짧은 이름을 그대로 씁니다
  (`[data-button-label]`이 있는 곳에만 이름을 넣습니다).

## 목록이 긴 화면

노래방 곡은 수백 개라 한 번에 다 그리면 스크롤 막대가 실낱같이 얇아져 목록의 끝을 가늠할 수 없습니다.
`karaoke.js`의 `PAGE_SIZE`만큼만 그리고, 아래 `N곡 더 보기`로 같은 만큼씩 이어 붙입니다.
좁은 화면은 한 곡이 세로로 두 배를 쓰므로 절반만 그립니다.

- 검색어·필터·정렬처럼 **목록의 내용이 달라지는** 동작에서는 `resetPaging()`으로 처음부터 다시 그립니다.
- 즐겨찾기처럼 목록이 그대로인 동작에서는 부르지 않습니다. 보던 자리가 접히면 안 되기 때문입니다.
- 랜덤 뽑기는 그려 둔 곡이 아니라 **조건에 맞는 곡 전체**에서 고릅니다.
